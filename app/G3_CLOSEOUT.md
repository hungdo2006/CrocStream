## Implemented components

- `internal/capture`: monitor enumeration, selected-source validation,
  per-monitor-aware DPI context and GDI capture on one locked OS thread.
  Bounded output DIB, aspect-preserving scaling/black letterbox and G2 packed
  RGBA normalization. Source removal/geometry change fails the session.
  Native resources are restored/deleted/released by their owning thread.
- `internal/preview`: Idle/Preparing/Previewing/Stopping/Error, explicit Start,
  1-slot latest-only capture queue before JPEG, bounded measurements, idempotent
  Stop, truthful 3s timeout and shutdown cleanup. JPEG quality 75.
- `internal/bridge`: `127.0.0.1:0`, exact Host/Origin, `/preview` only, token
  in WebSocket subprotocol offer (not query/URL), binary JPEG <=4 MiB, one
  authenticated viewer, latest-only send slot, 1s write deadline. Admission
  caps all HTTP/socket connections before handlers; Stop closes hijacked
  sockets as well as the listener. No inbound data channel.
- React/TypeScript canvas: true local preview, explicit consent label,
  display/resolution/FPS selection, settings lock, Start/Stop, measured
  capture/JPEG/render FPS, errors, keyboard focus/labels/status. One active
  ImageBitmap decode plus newest queued Blob; every bitmap is closed.
  Disposed generations cannot draw; Stop clears canvas.
- Wails service: trusted bindings for list/start/stop/stats. Numeric process
  diagnostics provide actual heap/goroutine/GDI/handle/working-set data.
  Assets/IPC logs are disabled so no bridge tokens or frames enter logs.
- `wails.yaml`: actual Wails 3.1 manifest/build route. Root `main_windows.go`
  matches the CLI's application-package expectation. Production executable
  generated by `wails3 build`; Go builds also work with CGO disabled.

The ordinary executable does not configure CDP. A separate `g3test` build
enables a temporary loopback debug port for automated WebView testing only.
The test binary shares application/capture/bridge code and embedded frontend
with production, with this explicit instrumentation difference.

## Tests and limits

Unit/integration tests cover:

- CONFIG/aspect fitting, Win32 ABI/bounded surface creation and 100 synthetic
  GDI allocate/restore/delete cycles.
- No capture before Start, malformed options, duplicate Start, missing source,
  100 fake-source lifecycles/token rotations, timeout keeps Stopping.
- Missing/null/foreign/wrong-scheme/wrong-port Origin, wrong/missing token,
  viewer/query denial, client cap, binary ownership, latest queue, socket
  close, parent cancellation, unexpected inbound data and slow-client deadline.
- ImageBitmap close on draw/error/disposal, latest-only pending Blob and
  generation invalidation; actual UI verifies canvas/render/Stop and keyboard.

GDI has no app-style capture-permission prompt on this desktop; the explicit
Start control/harness consent is required. Actual tests used one primary
1920×1080 display. HDR/protected content, physical display hot-unplug,
secondary/mixed-DPI monitors and real screen-reader narration need dedicated
manual coverage; no claim follows from the one-display test. Source failures
are covered with fakes, and topology changes are checked at capture time.

Process diagnostics refer to the Go application process, not aggregate
WebView2 subprocess RSS. Working-set/heap samples alone do not prove absence
of every leak. JPEG preview is local and separate from network lossless codec.
No remote-room, transport route, RTT or delta savings is fabricated.
